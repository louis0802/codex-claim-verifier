# Implementation design

Repository inspected: existing Python modules under claim_verifier/, .codex-plugin/plugin.json (0.1.0+Codex cachebuster), hooks/hooks.json, scripts/doctor.py and audit.py; unittest suite. No Node package exists. Work from an updated source copy under this task's outputs, preserving original local installation.

Use a root dependency-free ESM npm package (`claim-verifier`, bin cli/index.mjs). Node owns setup, environment detection, safe process spawning, config creation, private runtime bootstrap, marketplace registration, and Codex launch. Python stays responsible for existing diagnostics/audit and activation state. A small scripts/public_cli.py bridge shares diagnostic reading and audit rendering; preserve legacy script behavior.

Codex CLI observed supports plugin list --json (installed[] records: pluginId, version, enabled, source), plugin add --json, marketplace add --json and --ref. Use those supported commands, not conceptual codex-marketplace. Default release stages plugin payload under CODEX_HOME/claim-verifier/releases/<content digest> when it is inside HOME; otherwise under HOME/.agents/plugins/claim-verifier/releases/<content digest>, updates only the claim-verifier entry in the implicit ~/.agents/plugins/marketplace.json (backup, preserve other entries/order), then codex plugin add claim-verifier@personal. Respect an existing personal source for ordinary installed setup. Explicit source goes through marketplace add; validate and use its returned name. Remote sources are HTTPS Git/GitHub shorthand only; version is a safe Git ref. npm CLI release pins select bundled versions.

Runtime: probe existing Python 3.11+ paths first. If absent, download pinned Astral python-build-standalone macOS archive, verify baked SHA-256 before tar extraction into a private staging directory, validate archive member paths, probe interpreter and move into CODEX_HOME/claim-verifier/python. No shell profile changes. hooks/run.mjs chooses the setup-owned runtime binding or usable system Python and invokes the unchanged Python hook entry point. hooks definitions change to this launcher and therefore may require review.

State: claim_verifier/install_state.py uses fcntl lock and atomic private writes at CODEX_HOME/claim-verifier-installation.json (a common location independent of PLUGIN_DATA). Identity is manifest version plus digest of packaged executable/configuration runtime files; this detects hook and code changes even without version changes. Setup initializes or resets only when identity changes. After handle() successfully returns and the ledger is committed, the hook records event, identity, data path, and actual audit flag. Refuse overwrites from an older hook when setup already bound a newer identity. Missing session never qualifies. Hooks never inspect or mutate Codex trust.

Diagnostics discover PLUGIN_DATA, activation-recorded data, Codex's plugins/data/claim-verifier-personal, and fallback directories with de-duplication. Public doctor composes Codex installation, strict global config validation, private storage, current activation and audit persistence. Global config validation is independent of project overrides. READY is an operational status, not proof that claim content passed.

Security/failure: reject malformed identifiers, unsafe relative source/refs, symlinked setup-owned destinations and malformed JSON/config. Exclusive setup lock prevents concurrent setup races; state lock handles concurrent hooks. Stage payload and Python before atomic promotion, backup catalog before changed entry, preserve existing config with exclusive creation. Errors stop the workflow and include next action; --verbose shows bounded child output. Read-only dry-run must not invoke commands that can install/refresh.

Rollout: npm pack and local npx tarball smoke before publishing. No live trust or auth changes. Rollback: reinstall previous release through setup --upgrade; user config survives; changed identity requires fresh observation. Schema 1 accepts missing legacy optional settings without rewriting TOML.

Real Codex testing established source containment: local marketplace entries may not escape their root. An external CODEX_HOME therefore uses HOME-owned payload staging. Only root-owned macOS /var → /private/var and /tmp → /private/tmp system aliases are permitted by setup directory checks; symlinked managed destinations remain rejected. Equivalent data roots are canonicalized before reading to prevent duplicate audit summaries. All hooks observed with missing saved audit yields WAITING FOR AUDIT and new-task guidance, without repeating hook review.
